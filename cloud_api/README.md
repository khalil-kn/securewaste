# SecureWaste cloud API

The cloud side of SecureWaste receives **scan metadata only**: an event id, a timestamp, a
classification, a risk level and three counts. Document text, filenames, paths and matched
values never leave the local scanner (ADR-0006).

## Layout

| File | Purpose |
| --- | --- |
| `schema.sql` | The `scan_events` table and its indexes. The only place the DDL is written. |
| `db.py` | Connection handling, insert and read of one scan event. |
| `config.py` | Settings read from environment variables. |
| `validation.py` | The request contract: allowed keys, values and counts. Pure functions. |
| `auth.py` | Authentication (hashed per-employee bearer credentials), roles, permissions and ownership checks. |
| `routes.py` | The HTTP endpoints. |
| `app.py` | The application factory. |
| `__main__.py` | `python -m cloud_api`, the local entry point. |
| `../scripts/issue_credential.py` | Issues a credential for one employee (see Authentication). |

## Local database

The API needs PostgreSQL 16 or newer. The quickest way is a container:

```bash
podman run -d --name sw-pg \
  -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=securewaste_cloud \
  -p 5432:5432 docker.io/library/postgres:16-alpine

export CLOUD_DATABASE_URL=postgresql://postgres:postgres@localhost:5432/securewaste_cloud
```

A local PostgreSQL installation works the same way; only the URL changes.

The schema is a migration script: apply it before starting the API or running the tests.

```bash
podman exec -i sw-pg psql -U postgres -d securewaste_cloud < cloud_api/schema.sql
```

## Configuration

| Variable | Meaning |
| --- | --- |
| `CLOUD_DATABASE_URL` | PostgreSQL URL of the cloud database. |
| `CLOUD_API_HOST` | Address the API listens on. Default `127.0.0.1`. |
| `CLOUD_API_PORT` | Port the API listens on. Default `5001`. |
| `CLOUD_API_CREDENTIALS` | Per-employee credentials, comma separated: `sha256(token):role:employee_uuid:expires_at`. Generated by `scripts/issue_credential.py`. |
| `CLOUD_API_MAX_TOKEN_TTL_SECONDS` | Longest allowed credential lifetime. Default `7776000` (90 days). |

Copy `.env.example` to `.env` (which is git-ignored) before running the service. Never commit
real credentials. A malformed `CLOUD_API_CREDENTIALS` stops the application at startup, and the
error message never echoes the entry. When the variable is empty or unset, every protected
request is refused with `401`.

## Authentication and authorization

Every protected endpoint needs `Authorization: Bearer <token>`.

**Identity.** Each token belongs to exactly one employee. The server stores only the SHA-256
hash of the token, the role, the employee UUID and an expiry date, so a leaked configuration
cannot be replayed as a token, and a token always identifies who is acting.

**Roles and permissions.**

| Permission | `employee` | `security_officer` | `admin` |
| --- | :---: | :---: | :---: |
| Store a scan event (owned by the caller) | yes | no | yes |
| Read own scan events | yes | yes | yes |
| Read any scan event | no | yes | yes |
| Read the audit log | no | yes | no |
| Manage users | no | no | yes |

Any other role is refused when the configuration is loaded. The matrix lives in
`ROLE_PERMISSIONS` in `auth.py`.

**Ownership.** The owner of a scan event is always the employee of the validated token. It is
never taken from the request: `employee_id` is a forbidden body field and is refused with
`400`, even when it matches the token.

**Errors.** `401` means the token is missing, unknown or expired. The message is identical for
the three cases, so a caller cannot probe which tokens exist. `403` means the token is valid but
its role may not perform the action, or the employee asked for data owned by someone else.
Responses to failed authentication carry `Cache-Control: no-store`.

### Issuing a credential

```bash
python scripts/issue_credential.py <employee_uuid> <role> --ttl-days 30
```

The script prints the plaintext **token** once (give it to that employee over a safe channel)
and the **entry** to append to `CLOUD_API_CREDENTIALS`. The admin role also needs `--allow-admin`.
The lifetime cannot exceed `CLOUD_API_MAX_TOKEN_TTL_SECONDS`.

### Rotation and revocation

1. Issue a new credential for the same employee and add its entry.
2. Give the employee the new token.
3. Remove the old entry and restart the API.

Both tokens work during the overlap. To revoke a token immediately, remove its entry and
restart. Expiry is mandatory, so no credential lives forever. (Instant revocation without a
restart is not implemented yet.)

## Endpoints

### `GET /health`

Public liveness check. It says nothing about the database and holds no secret.

```bash
curl http://127.0.0.1:5001/health
```

```json
{ "status": "ok", "service": "securewaste-cloud" }
```

### `POST /api/v1/scans`

Stores the metadata of one scan event. Requires the permission to store scans (`employee` or
`admin`). The event is owned by the employee of the token.

```bash
curl -X POST http://127.0.0.1:5001/api/v1/scans \
  -H "Authorization: Bearer $CLOUD_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "event_id": "3f0c1d2e-4b5a-4c6d-8e9f-0a1b2c3d4e5f",
    "timestamp": "2026-11-20T10:30:00Z",
    "classification": "Confidential",
    "risk": "High",
    "counts": { "email": 2, "phone": 1, "keyword": 3 }
  }'
```

```json
{ "event_id": "3f0c1d2e-4b5a-4c6d-8e9f-0a1b2c3d4e5f", "status": "stored" }
```

The contract:

- `event_id`: a UUID, unique in the table.
- `timestamp`: an ISO 8601 date and time with a timezone offset.
- `classification`: one of `Public`, `Internal`, `Confidential`, `Highly Confidential`.
- `risk`: optional. One of `Low`, `Medium`, `High`, or omitted/null. Overall risk assessment is deferred to Sprint 4 (SCRUM-46); a missing value is never fabricated.
- `counts`: an object with the keys `email`, `phone` and `keyword`, each a non-negative integer.

Any other key is refused, so document text, file names, paths and matched values cannot reach
the database even by accident. `employee_id` is one of those forbidden keys.

| Status | When |
| --- | --- |
| `201` | The scan event is stored. |
| `400` | The body is not valid JSON or does not match the contract, including a forbidden `employee_id`. The response lists the fields to fix. |
| `401` | The bearer token is missing, unknown or expired. |
| `403` | The role of the token may not store scan events. |
| `409` | This `event_id` is already stored. |
| `413` | The body is larger than 8 KiB. |
| `415` | The `Content-Type` is not `application/json`. |
| `503` | The database cannot be reached. |

### `GET /api/v1/scans/<event_id>`

Reads one stored scan event.

| Status | When |
| --- | --- |
| `200` | The event is returned. |
| `401` | The bearer token is missing, unknown or expired. |
| `403` | An `employee` asked for an event owned by someone else, or for an unattributed historical row. |
| `404` | The id is not a UUID or no such event exists. |
| `503` | The database cannot be reached. |

An `employee` may read only their own events. `security_officer` and `admin` may read any event,
including unattributed historical rows.

## Running the API

```bash
export CLOUD_DATABASE_URL=postgresql://postgres:postgres@localhost:5432/securewaste_cloud
python scripts/issue_credential.py 11111111-2222-3333-4444-555555555555 employee --ttl-days 7
# copy the printed entry into the environment, keep the printed token for requests:
export CLOUD_API_CREDENTIALS="<ENTRY>"
python -m cloud_api
```

PowerShell: use `$env:CLOUD_DATABASE_URL = "..."` and `$env:CLOUD_API_CREDENTIALS = "<ENTRY>"`.
Serve the API over HTTPS outside a local machine: bearer tokens travel in clear text otherwise.

## Employee attribution (SCRUM-45)

`scan_events.employee_id` is populated server-side from the validated credential. The client
never sends `employee_id`. Rows stored before attribution existed keep `employee_id = NULL`
(unattributed). Only `security_officer` and `admin` can read them.

## Migration (SCRUM-45)

Numbered SQL files live in `cloud_api/migrations/`. Apply them in order:

```bash
psql "$CLOUD_DATABASE_URL" -f cloud_api/migrations/000_schema_migrations.sql
psql "$CLOUD_DATABASE_URL" -f cloud_api/migrations/001_scrum45_employee_and_nullable_risk.sql
```

Historic rows keep their `risk` value and get `employee_id = NULL` (unattributed). Roll back by
restoring from a backup (`pg_dump`) taken before migration; the ALTERs are not automatically
reversible.
